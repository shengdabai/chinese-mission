# chinese-mission — 建议与需求（nlpm advise · 2026-10-30 · HEAD 6d22abf）

## 一句话判断
中文使命是一个 AI 中文任务对话产品。它已经公开上线，并展示了 ¥28/月 的定价页，但还没有接支付；按门槛阶梯，它仍在门 1，而且没有自用记录。当前分支 HEAD 的 `/api/chat` 和 `/api/debrief` 没有鉴权，也没有服务端限流，任何人都能直接消耗付费模型额度。所以下一步是先把本分支与 origin/main 合并，再把限流计数迁到共享存储。origin/main 已有进程内限流、已跟踪 lockfile、已升级 Next.js 安全补丁。

## 画像
- **入口**：对已上线产品做体检，不针对单一变更。当前分支 `ai/b12-20261001` 的改动是 SEO 重写、定价页、iOS 隐私清单和 API 入参加固。
- **能力勾选**：
  - 服务端 ✓：3 个 Next.js API 路由，分别调用付费 LLM 和 Edge TTS。
  - 登录 ✗。
  - 支付 ✗：只有定价页和 Paywall 界面，RevenueCat 未接（`src/lib/entitlements.ts:7-9`）。
  - 数据库 ✗：进度存在浏览器 localStorage。
  - 公开交付 ✓：Vercel 生产站允许收录（`src/app/layout.tsx:18`），sitemap 含 `/pricing`（`src/app/sitemap.ts:7`）；iOS 壳通过 `server.url` 加载远端站点（`capacitor.config.ts:8`）。
- **风险级别**：高。公开接口没有鉴权，却直接花钱。同时本分支与生产主线分叉：`git rev-list --left-right --count HEAD...origin/main → 4	16`。
- **当前门**：门 1，但没有门 1 证据（`.omc/` 下没有 `usage-log.md`）。定价已经公开，超前于门槛证据。
- **部署目标**：Vercel 项目 `chinese-mission`，用过 GitHub 自动部署和 CLI 生产部署两种方式（`MISSION_BUILD_LOG.md:67-69`）。Dockerfile 是备用路径（`Dockerfile:30`）。

**级别调整**：产品已公开，所以 P02 从 P2 升到 P1。P07 从 P0 降到 P1，因为密钥值不在 git 中（gitleaks 0 命中），暴露面是会话记录。其余规则按默认级别。

## 可直接贴进 issue 的需求

### [P0] 付费 AI 与 TTS 接口在服务端限额
- 背景：HEAD 的 `/api/chat` 和 `/api/debrief` 不鉴权、不限流（`src/app/api/chat/route.ts:38-63`）。免费额度只存在浏览器 localStorage 里。main 的限流计数存在进程内存，Vercel 多实例之间不共享。
- 需求：三个 API 路由调用模型或 TTS 之前，先在共享存储（Upstash/KV/Redis）里检查配额，配额分"单客户端"和"全局"两层；超额返回 429。
- 验收标准：同一客户端超过上限后返回 429；重启后、两个实例之间计数保持一致；全局上限触发后，模型调用次数不再增加。
- 验证层：integration
- 相关规则：P05、P11

## 本轮不做

- **20 个任务 × 3 视口的全量 Playwright 回归**：本轮只要求 AI 路径一条集成测试，加定价页 e2e。
